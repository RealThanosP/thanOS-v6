\section[Άσκηση 1: System Calls \& Πρόγραμμα Χρήστη]{Εντοπισμός System Calls \& Ανάλυση Προγράμματος Χρήστη}

\subsection*{1. Αρχεία Ορισμού Κλήσεων Συστήματος}

Στον πηγαίο κώδικα του xv6, ο ορισμός και η διεπαφή (interface) των κλήσεων συστήματος (system calls) για τα προγράμματα χρήστη κατανέμονται σε τρία βασικά αρχεία:

\begin{itemize}
    \item \textbf{\texttt{include/user.h}}: Περιέχει τις δηλώσεις των συναρτήσεων των διαθέσιμων κλήσεων συστήματος για το user space (π.χ. \texttt{int open(const char*, int)}, \texttt{int read(int, void*, int)}, \texttt{int write(int, const void*, int)}, \texttt{int close(int)}, \texttt{int exit(void)}, κ.λπ.). Με τον τρόπο αυτό, ο compiler γνωρίζει τους τύπους ορισμάτων και επιστροφής κατά τη συγγραφή προγραμμάτων χρήστη.
    
    \item \textbf{\texttt{include/syscall.h}}: Ορίζει τα system call numbers (π.χ. \texttt{\#define SYS\_open 15}, \texttt{\#define SYS\_read 5}). 
    Οι κωδικοί αυτοί χρησιμοποιούνται τόσο από το user space για την επιλογή της κλήσης, 
    όσο και από τον πυρήνα για την ανάκτηση της κατάλληλης συνάρτησης χειρισμού από τον πίνακα δεικτών \texttt{syscalls[]}.
    
    \item \textbf{\texttt{ulib/usys.S}}: Περιέχει τα assembly wrappers που εκτελούνται στο user space. 
    Μέσω του \texttt{SYSCALL(name)}:

\begin{lstlisting}[language=C, aboveskip=2pt, belowskip=2pt, basicstyle=\ttfamily\scriptsize]
#define SYSCALL(name) \
  .globl name; name: movl $SYS_ ## name, %eax; int $T_SYSCALL; ret
\end{lstlisting}
    Φορτώνεται ο αντίστοιχος κωδικός στον καταχωρητή \texttt{\%eax} και εκτελείται η διακοπή λογισμικού \texttt{int \$T\_SYSCALL} (\texttt{trap 64}), 
    μεταφέροντας τον έλεγχο από το User Space (Ring 3) στον Πυρήνα (Ring 0).
\end{itemize}

\clearpage


\subsection*{1. Επιλογή \& Ανάλυση Προγράμματος Χρήστη (\texttt{user/cat.c})}

Για την ανάλυση επιλέγεται το πρόγραμμα χρήστη \texttt{cat} (\texttt{user/cat.c}), το οποίο αναλαμβάνει το άνοιγμα ενός 
ή περισσότερων αρχείων και την εμφάνιση των περιεχομένων τους στην πρότυπη έξοδο (τερματικό).

\subsubsection*{Πηγαίος Κώδικας (\texttt{user/cat.c})}
\begin{lstlisting}[language=C, caption={Πηγαίος κώδικας του προγράμματος cat (user/cat.c)}]
#include "types.h"
#include "stat.h"
#include "user.h"

char buf[512];

void cat(int fd) {
  int n;
  while((n = read(fd, buf, sizeof(buf))) > 0)
    write(1, buf, n);
  if(n < 0){
    printf(1, "cat: read error\n");
    exit();
  }
}

int main(int argc, char *argv[]) {
  int fd, i;
  if(argc <= 1){
    cat(0);
    exit();
  }
  for(i = 1; i < argc; i++){
    if((fd = open(argv[i], 0)) < 0){
      printf(1, "cat: cannot open %s\n", argv[i]);
      exit();
    }
    cat(fd);
    close(fd);
  }
  exit();
}
\end{lstlisting}

\clearpage
\subsubsection*{Ανάλυση Ροής Εκτέλεσης \& Κλήσεων Συστήματος}

\begin{enumerate}
    \item \textbf{Διαχείριση Ορισμάτων \& Είσοδος}:
    \begin{itemize}
        \item Εάν δεν δοθούν ορίσματα αρχείων στη γραμμή εντολών (\texttt{argc <= 1}), το πρόγραμμα καλεί τη συνάρτηση \texttt{cat(0)}, 
        διαβάζοντας απευθείας από την πρότυπη είσοδο (standard input, περιγραφέας αρχείου 0), και στη συνέχεια τερματίζει με 
        \texttt{exit()}.
        \item Εάν δοθούν ονόματα αρχείων (\texttt{argc > 1}), το \texttt{cat} επεξεργάζεται διαδοχικά κάθε αρχείο \texttt{argv[i]} 
        μέσω ενός βρόχου \texttt{for}.
    \end{itemize}

    \item \textbf{Άνοιγμα Αρχείου (\texttt{SYS\_open})}:
    \begin{itemize}
        \item Για κάθε αρχείο εκτελείται η κλήση συστήματος \texttt{open(argv[i], 0)} (\texttt{SYS\_open}, κωδικός 15) με flag ανάγνωσης 
        (\texttt{O\_RDONLY}).
        \item Εάν η επιστρεφόμενη τιμή είναι αρνητική (\texttt{fd < 0}), το αρχείο δεν κατέστη δυνατό να ανοιχθεί. 
        Το πρόγραμμα εκτυπώνει μήνυμα σφάλματος και τερματίζει καλώντας \texttt{exit()} (\texttt{SYS\_exit}, κωδικός 2).
    \end{itemize}

    \item \textbf{Ανάγνωση Περιεχομένου (\texttt{SYS\_read})}:
    \begin{itemize}
        \item Εντός της συνάρτησης \texttt{cat(fd)}, εκτελείται επαναληπτικά η κλήση συστήματος \texttt{read(fd, buf, sizeof(buf))} 
        (\texttt{SYS\_read}, κωδικός 5) για την ανάγνωση δεδομένων έως 512 bytes στον ενδιάμεσο buffer \texttt{buf}.
        \item Η τιμή επιστροφής \texttt{n} αντιστοιχεί στα πραγματικά bytes που διαβάστηκαν.
    \end{itemize}

    \item \textbf{Εγγραφή στην Έξοδο (\texttt{SYS\_write})}:
    \begin{itemize}
        \item Για όσο διάστημα \texttt{n > 0}, καλείται η \texttt{write(1, buf, n)} (\texttt{SYS\_write}, κωδικός 16), 
        αποστέλλοντας τα δεδομένα του buffer στον περιγραφέα αρχείου 1 (standard output), που αντιστοιχεί στο τερματικό.
    \end{itemize}

    \item \textbf{Τερματισμός Βρόχου Ανάγνωσης}:
    \begin{itemize}
        \item Τα βήματα 3 και 4 επαναλαμβάνονται έως ότου η \texttt{read()} επιστρέψει \texttt{0}, 
        υποδεικνύοντας το τέλος του αρχείου (EOF).
        \item Εάν η \texttt{read()} επιστρέψει αρνητική τιμή (\texttt{n < 0}), έχει προκύψει σφάλμα ανάγνωσης, τυπώνεται σχετικό 
        μήνυμα και καλείται \texttt{exit()} (\texttt{SYS\_exit}, κωδικός 2).
    \end{itemize}

    \item \textbf{Κλείσιμο Περιγραφέα (\texttt{SYS\_close})}:
    \begin{itemize}
        \item Μόλις ολοκληρωθεί η ανάγνωση του αρχείου, καλείται η \texttt{close(fd)} (\texttt{SYS\_close}, κωδικός 21), 
        αποδεσμεύοντας τον περιγραφέα αρχείου και τους σχετικούς πόρους του πυρήνα.
    \end{itemize}

    \item \textbf{Τερματισμός Διεργασίας (\texttt{SYS\_exit})}:
    \begin{itemize}
        \item Αφού ολοκληρωθεί η επεξεργασία όλων των αρχείων, καλείται η \texttt{exit()} (\texttt{SYS\_exit}, κωδικός 2), 
        η οποία απελευθερώνει τη διεργασία και επιστρέφει τον έλεγχο στο shell.
    \end{itemize}
\end{enumerate}

\section{Άσκηση 2: Δημιουργία Προγράμματος Χρήστη}

\subsection*{2. Περιγραφή \& Σκοπός Προγράμματος}
Υλοποιήθηκε το πρόγραμμα χρήστη \texttt{touch} (\texttt{user/touch.c}), το οποίο αναλαμβάνει τη δημιουργία νέων κενών αρχείων με δικαιώματα ανάγνωσης και εγγραφής (Read/Write). Εάν το αρχείο προϋπάρχει, ανοίγει κανονικά χωρίς να τροποποιηθεί το περιεχόμενό του. Η σύνταξη της εντολής επιτρέπει τη δημιουργία ενός ή περισσότερων αρχείων ταυτόχρονα: \texttt{touch <file1> [file2 ...]}.

\subsection*{2. Πηγαίος Κώδικας (\texttt{user/touch.c})}
\begin{lstlisting}[language=C, caption={Υλοποίηση προγράμματος χρήστη touch (user/touch.c)}]
#include "types.h"
#include "stat.h"
#include "user.h"
#include "fcntl.h"

int touch(void) {
    // Return flags for creating a new file with READ/WRITE permissions
    return O_CREATE | O_RDWR;
}

int main(int argc, char *argv[]) {
    int fd, i;

    if (argc < 2) {
        printf(2, "Usage: touch file1 file2 ...\n");
        exit();
    }

    for (i = 1; i < argc; i++) {
        fd = open(argv[i], touch());
        if (fd < 0) {
            printf(2, "touch: cannot create %s\n", argv[i]);
            exit();
        }
        close(fd);
    }
    exit();
}
\end{lstlisting}

\section{Άσκηση 3: Ανάλυση της Κλήσης Συστήματος \texttt{uptime}}

\subsection*{1. Σημεία Αναφοράς στον Πηγαίο Κώδικα}
Η κλήση συστήματος \texttt{uptime} δηλώνεται και χρησιμοποιείται στα εξής αρχεία του πηγαίου κώδικα:
\begin{itemize}
    \item \textbf{\texttt{include/syscall.h}}: Ορίζεται ο κωδικός της κλήσης (\texttt{\#define SYS\_uptime 14}).
    \item \textbf{\texttt{include/user.h}}: Περιλαμβάνει τη δήλωση για το user space (\texttt{int uptime(void);}).
    \item \textbf{\texttt{ulib/usys.S}}: Περιέχει το assembly stub (\texttt{SYSCALL(uptime)}) που παράγει το trap/interrupt.
    \item \textbf{\texttt{kernel/syscall.c}}: Δηλώνεται η \texttt{sys\_uptime(void)} και καταχωρίζεται στον πίνακα \texttt{syscalls[]}.
    \item \textbf{\texttt{kernel/sysproc.c}}: Υλοποιείται η συνάρτηση εξυπηρέτησης \texttt{sys\_uptime(void)} στον πυρήνα.
    διεργασίες.
\end{itemize}

\subsection*{2. Ανάλυση Υλοποίησης (\texttt{sys\_uptime})}
Η συνάρτηση \texttt{sys\_uptime()} επιστρέφει το πλήθος των διακοπών του ρολογιού συστήματος (clock tick interrupts) 
από τη στιγμή εκκίνησης του λειτουργικού συστήματος. 

Η καθολική μεταβλητή \texttt{ticks} αυξάνεται σε κάθε διακοπή χρονιστή στο αρχείο \texttt{kernel/trap.c}.

Η χρήση του μηχανισμού κλειδώματος \texttt{tickslock} είναι απαραίτητη καθώς 
εξασφαλίζει ότι η ανάγνωση της τιμής της μεταβλητής \texttt{ticks} πραγματοποιείται ατομικά και με συνέπεια, 
αποτρέποντας συνθήκες ανταγωνισμού.

\begin{lstlisting}[language=C, caption={Υλοποίηση sys\_uptime στο kernel/sysproc.c}]
// return how many clock tick interrupts have occurred since start.
int sys_uptime(void) {
  uint xticks;
  acquire(&tickslock);
  xticks = ticks;
  release(&tickslock);
  return xticks;
}
\end{lstlisting}

\section{Άσκηση 4: Ροή Εκτέλεσης System Calls στον Πυρήνα}

\subsection*{1. Εντοπισμός Συνάρτησης Εκτέλεσης System Calls}
Η κεντρική συνάρτηση αποστολής και εκτέλεσης όλων των κλήσεων συστήματος στον πυρήνα είναι η \texttt{syscall(void)}, 
η οποία βρίσκεται στο αρχείο \texttt{kernel/syscall.c}.

\subsection*{2. Σειρά Ενεργειών \& Μηχανισμός Εκτέλεσης System Calls}

\begin{lstlisting}[language=C, caption={Υλοποίηση της συνάρτησης syscall στο kernel/syscall.c}]
void syscall(void) {
  int num = proc->tf->eax;
  if (num > 0 && num < NELEM(syscalls) && syscalls[num]) {
    proc->tf->eax = syscalls[num]();
  } else {
    cprintf("%d %s: unknown sys call %d\n", proc->pid, proc->name, num);
    proc->tf->eax = -1;
  }
}
\end{lstlisting}

Η πλήρης ακολουθία ενεργειών κατά την κλήση ενός system call στο xv6 εξελίσσεται ως εξής:

\begin{enumerate}[topsep=1pt, itemsep=0.5pt, parsep=0pt]
    \item \textbf{Κλήση από το User Space}: Το πρόγραμμα χρήστη καλεί τη συνάρτηση-διεπαφή (π.χ. \texttt{read()}). 
    Το assembly stub στο \texttt{ulib/usys.S} τοποθετεί τον αριθμό της κλήσης (\texttt{SYS\_read}) στον καταχωρητή \texttt{\%eax} 
    και εκτελεί τη διακοπή λογισμικού \texttt{int \$T\_SYSCALL} (trap).
    \item \textbf{Μετάβαση σε Kernel Mode}: Ο επεξεργαστής μεταβαίνει αυτόματα σε Ring 0, αποθηκεύει τους καταχωρητές στη στοίβα 
    πυρήνα (\texttt{struct trapframe}) και μεταφέρει την εκτέλεση στον γενικό χειριστή \texttt{alltraps} (\texttt{kernel/trapasm.S}).
    \item \textbf{Δρομολόγηση μέσω της \texttt{trap()}}: Η συνάρτηση \texttt{trap()} (\texttt{kernel/trap.c}) διαπιστώνει ότι πρόκειται 
    για \texttt{T\_SYSCALL} και καλεί τη συνάρτηση \texttt{syscall()}.
    \item \textbf{Ανάγνωση Αριθμού Κλήσης}: Η \texttt{syscall()} διαβάζει τον αριθμό της κλήσης από το trap frame της 
    διεργασίας (\texttt{num = proc->tf->eax}).
    \item \textbf{Έλεγχος Ορίων (Bounds Checking)}: Επαληθεύεται ότι \texttt{num > 0}, \texttt{num < NELEM(syscalls)} και ότι υπάρχει
    έγκυρος δείκτης συνάρτησης (\texttt{syscalls[num] != NULL}).
    \item \textbf{Εκτέλεση \& Αποθήκευση Αποτελέσματος}: Εφόσον ο έλεγχος επιτύχει, καλείται η συνάρτηση του πυρήνα
    (\texttt{syscalls[num]()}) και η τιμή επιστροφής αποθηκεύεται στο \texttt{proc->tf->eax}.
    \item \textbf{Διαχείριση Σφάλματος}: Εάν ο αριθμός δεν είναι έγκυρος, εκτυπώνεται μήνυμα σφάλματος μέσω \texttt{cprintf()} 
    και αποδίδεται \texttt{-1} στον \texttt{\%eax}.
    \item \textbf{Επιστροφή στο User Space}: Ο πυρήνας εκτελεί την \texttt{trapret}, αποκαθιστά τους καταχωρητές 
    (με το αποτέλεσμα στον \texttt{\%eax}) και με την \texttt{iret} επιστρέφει στο User Space.
\end{enumerate}

\section{Άσκηση 5: Προσθήκη System Call (\texttt{getfavnum})}

\subsection*{1. Τροποποιήσεις στον Πυρήνα \& User Interface}
Σύμφωνα με τις απαιτήσεις της άσκησης υλοποιήθηκε η κλήση συστήματος επιστροφής του αγαπημένου αριθμού. 
Στο repository \texttt{thanOS-v6} έχει ενσωματωθεί ως \texttt{favnum} (\texttt{getfavnum}), τροποποιώντας τα εξής αρχεία:
\begin{itemize}
    \item \textbf{\texttt{include/syscall.h}}: Ορίστηκε ο μοναδικός κωδικός (\texttt{\#define SYS\_favnum 29}).
    \item \textbf{\texttt{ulib/usys.S}}: Προστέθηκε το assembly wrapper (\texttt{SYSCALL(favnum)}).
    \item \textbf{\texttt{include/user.h}}: Δηλώθηκε το πρωτότυπο της διεπαφής (\texttt{int favnum(void);}).
    \item \textbf{\texttt{kernel/syscall.c}}: Δηλώθηκε η \texttt{extern int sys\_favnum(void);} και καταχωρίστηκε στον πίνακα δεικτών 
    \texttt{syscalls[]}: \texttt{[SYS\_favnum] sys\_favnum}.
    \item \textbf{\texttt{kernel/sysproc.c}}: Υλοποιήθηκε η συνάρτηση εξυπηρέτησης του πυρήνα:
\end{itemize}

\begin{lstlisting}[language=C, caption={Η trivial υλοποίηση sys\_favnum στο kernel/sysproc.c}]
// returns my favourite number
int sys_favnum(void) {
  return 42;
}
\end{lstlisting}

\section{Άσκηση 6: System Call Τερματισμού (\texttt{halt} / \texttt{shutdown})}

\subsection*{1. Ανάλυση της Συνάρτησης \texttt{outw} \& Port I/O}
Για να επιτευχθεί ο τερματισμός της εικονικής μηχανής και η επιστροφή στο host σύστημα, απαιτείται άμεση επικοινωνία με το υλικό του QEMU. 
Το xv6 δεν παρέχει εξ ορισμού μηχανισμό τερματισμού (power-off), επομένως υλοποιήθηκε η νέα κλήση \texttt{halt}.

\paragraph{Υλοποίηση της \texttt{outw} (\texttt{include/x86.h}):}
Η επικοινωνία με τις θύρες I/O γίνεται μέσω της \texttt{outw}:

\begin{lstlisting}[language=C, caption={Υλοποίηση της outw στο include/x86.h}]
static inline void outw(ushort port, ushort data) {
  asm volatile("out %0,%1" : : "a" (data), "d" (port));
}
\end{lstlisting}

\paragraph{Λειτουργία \& Επίπεδο Προνομίων CPU:}
\begin{itemize}
    \item \textbf{Port-Mapped I/O (PMIO)}: Στην αρχιτεκτονική x86 υφίσταται διακριτός χώρος διευθύνσεων I/O (Port-Mapped I/O), ανεξάρτητος από τη RAM, 
    προσπελάσιμος αποκλειστικά μέσω των assembly εντολών \texttt{in} και \texttt{out}.
    \item \textbf{Καταχωρητές \& Inline Assembly}: Το όρισμα \texttt{data} (16-bit word) δεσμεύεται στον καταχωρητή \texttt{\%ax} 
    (constraint \texttt{"a"}) και το \texttt{port} στον \texttt{\%dx} (constraint \texttt{"d"}). 
    Η assembly εντολή \texttt{out \%ax, \%dx} αποστέλλει τα 16 bits της τιμής στη δηλωθείσα θύρα I/O.
    \item \textbf{Προνομιακές Εντολές}: Οι εντολές \texttt{in} και \texttt{out} επιτρέπεται να εκτελεστούν αποκλειστικά όταν το επίπεδο προνομίων (CPL) βρίσκεται σε Kernel Mode (Ring 0). 
    Εάν εκτελεστούν σε User Mode (Ring 3), ο επεξεργαστής παράγει άμεσα εξαίρεση γενικής προστασίας (\textbf{General Protection Fault - \texttt{\#GP}}).
\end{itemize}

\paragraph{Διευθύνσεις Θυρών (Ports) \& Magic Values (ACPI):}
\begin{itemize}
    \item \textbf{Port \texttt{0x604} (QEMU ACPI)}: Στο chipset PIIX4 του QEMU, η βάση του ACPI I/O space ορίζεται στη διεύθυνση \texttt{0x600}. 
    Η θύρα στο offset \texttt{+0x04} (\texttt{0x604}) αντιστοιχεί στον καταχωρητή ελέγχου \textbf{\texttt{PM1a\_CNT}} (\textit{Power Management 1 Control Register}).
    \item \textbf{Τιμή \texttt{0x2000} (\texttt{SLP\_EN})}: Σύμφωνα με τις προδιαγραφές ACPI, το \textbf{bit 13} αποτελεί τη σημαία \texttt{SLP\_EN} (\textit{Sleep Enable}), 
    ενώ τα \textbf{bits 10--12} (\texttt{SLP\_TYP}) με τιμή \texttt{000} σηματοδοτούν την κατάσταση πλήρους τερματισμού \texttt{S5} (\textit{Soft-Off}). 
    Η εγγραφή του \texttt{0x2000} (\texttt{0010\_0000\_0000\_0000}$_2$) στον \texttt{PM1a\_CNT} δίνει εντολή στο ACPI του QEMU να κλείσει την εικονική μηχανή.
    \item \textbf{Port \texttt{0xB004}}: Χρησιμοποιείται ως fallback διεύθυνση ACPI για παλαιότερες εκδόσεις του QEMU, που έτυχε να χρησιμοποιώ.
\end{itemize}

\clearpage
\subsection*{2. Υλοποίηση Κλήσης Συστήματος (\texttt{sys\_halt})}
Για την πλήρη ένταξη της κλήσης συστήματος \texttt{halt} στο λειτουργικό σύστημα, τροποποιήθηκαν τα εξής αρχεία:
\begin{itemize}
    \item \textbf{\texttt{include/syscall.h}}: Ορισμός κωδικού κλήσης (\texttt{\#define SYS\_halt 28}).
    \item \textbf{\texttt{include/user.h}}: Δήλωση πρωτοτύπου χρήστη (\texttt{void halt(void);}).
    \item \textbf{\texttt{ulib/usys.S}}: Προσθήκη assembly stub (\texttt{SYSCALL(halt)}).
    \item \textbf{\texttt{kernel/syscall.c}}: Δήλωση \texttt{extern int sys\_halt(void);} και καταχώριση στον πίνακα \texttt{syscalls[]}: \texttt{[SYS\_halt] sys\_halt}.
    \item \textbf{\texttt{kernel/sysproc.c}}: Υλοποίηση της συνάρτησης εξυπηρέτησης του πυρήνα:
\end{itemize}

\begin{lstlisting}[language=C, caption={Υλοποίηση sys\_halt στο kernel/sysproc.c}]
// Shutdown xv6
int sys_halt(void) {
  // QEMU uses port 0x604 for ACPI power-off
  outw(0x604, 0x2000);
  // Fallback for older QEMU versions
  outw(0xB004, 0x2000);
  return 0;
}
\end{lstlisting}

\section{Άσκηση 7: Καταμέτρηση Κλήσεων (\texttt{getcount})}

\subsection*{1. Αρχιτεκτονική Καταμέτρησης στον Πυρήνα}
Για την καταμέτρηση των εκτελέσεων κάθε κλήσης συστήματος, δηλώθηκε στον πυρήνα (\texttt{kernel/syscall.c}) 
ο καθολικός πίνακας \texttt{syscall\_counts[NELEM(syscalls)]}, με αρχικοποίηση όλων των στοιχείων στο μηδέν. 

Μέσα στην κεντρική συνάρτηση \texttt{syscall(void)}, μετά την επιτυχή εκτέλεση της εκάστοτε κλήσης, αυξάνεται 
ο αντίστοιχος μετρητής: \texttt{syscall\_counts[num]++}.

\subsection*{2. Υλοποίηση \texttt{sys\_getcount} (\texttt{kernel/sysproc.c})}
Ο handler ανακτά το πρώτο όρισμα (\texttt{argint}), ελέγχει τα όρια και επιστρέφει τον μετρητή:
Ο πίνακας \texttt{syscall\_counts} και το μήκος του \texttt{syscall\_counts\_len} ορίζονται στο \texttt{kernel/syscall.c} 
και είναι προσβάσιμα στο \texttt{kernel/sysproc.c} μέσω δηλώσεων \texttt{extern}.

\begin{lstlisting}[language=C, caption={Υλοποίηση sys\_getcount στο kernel/sysproc.c}]
extern int syscall_counts[];
extern const int syscall_counts_len;

int sys_getcount(void) {
  int sc;
  if (argint(0, &sc) < 0 || sc < 0 || sc >= syscall_counts_len) return -1;
  return syscall_counts[sc];
}
\end{lstlisting}

\subsection*{3. Πρόγραμμα Χρήστη (\texttt{user/syscount.c})}
\begin{lstlisting}[language=C, caption={Πρόγραμμα χρήστη syscount (user/syscount.c)}]
#include "types.h"
#include "user.h"

int main(int argc, char *argv[]) {
  if (argc != 2) { printf(2, "Usage: %s <syscall_num>\n", argv[0]); exit(); }
  int num = atoi(argv[1]);
  int count = getcount(num);
  if (count < 0) { printf(2, "syscount: invalid syscall %d\n", num); exit(); }
  printf(1, "System call %d execution count: %d\n", num, count);
  exit();
}
\end{lstlisting}

\subsection*{4. Πειραματική Επαλήθευση \& Αποτελέσματα}
\begin{lstlisting}[style=termstyle, caption={Δοκιμές καταμέτρησης με το διαγνωστικό πρόγραμμα forktest}]
$ forktest
fork test
fork test OK
$ syscount 1
System call 1 execution count: 65
\end{lstlisting}
Με όριο 64 διεργασιών και ήδη ενεργές τις init, shell και forktest, το forktest δημιουργεί 61 παιδιά και πραγματοποιεί μία επιπλέον αποτυχημένη κλήση fork(). 
Ο καθολικός μετρητής περιλαμβάνει επίσης τη δημιουργία του shell από την init και την εκκίνηση των forktest και syscount από το shell. 
Έτσι, σε καθαρή εκκίνηση χωρίς άλλες διεργασίες ή προηγούμενες κλήσεις fork(), προκύπτουν συνολικά 65 κλήσεις,  
61 (από το fork test) + 1 (αποτυχημένη) + 1 (της init) + 2 (του shell).

\section{Άσκηση 8: Τυχαίος Τερματισμός (\texttt{killrandom})}


\subsection*{1. Γεννήτρια Ψευδοτυχαίων Αριθμών στον Πυρήνα}
Για την παραγωγή ψευδοτυχαίων αριθμών εντός του πυρήνα υλοποιήθηκε μια γεννήτρια βασισμένη στον αλγόριθμο \textbf{Xorshift32} (\texttt{kernel/proc.c}). 
Ο αλγόριθμος εκτελεί διαδοχικές πράξεις bitwise shift και XOR πάνω σε μια εσωτερική κατάσταση (\texttt{rand\_state}), παράγοντας ψευδοτυχαίους αριθμούς 32-bit.

\begin{lstlisting}[language=C, caption={Υλοποίηση του αλγορίθμου Xorshift32 στο kernel/proc.c}]
// Generates a 32-bit pseudo-random unsigned integer
unsigned int rand(void) {
  unsigned int x = rand_state;
  x ^= x << 13;
  x ^= x >> 17;
  x ^= x << 5;
  rand_state = x;
  return x;
}
\end{lstlisting}

\subsection*{2. Ανάκτηση PID, Συγχρονισμός \& Προστασία Κρίσιμων Διεργασιών}
Κατά τον σχεδιασμό της κλήσης συστήματος \texttt{sys\_killrandom()}, τηρούνται αυστηρά κριτήρια ασφαλείας και ορθού συγχρονισμού:

\begin{itemize}
    \item \textbf{Προστασία κρίσιμων διεργασιών}: Εξαιρείται ρητά η αρχική διεργασία \texttt{init} (\texttt{PID 1}), καθώς ο τερματισμός της οδηγεί σε κατάρρευση (\textit{kernel panic}), 
    καθώς και η ίδια η τρέχουσα διεργασία (\texttt{proc}), αποτρέποντας ακούσιο αυτοτερματισμό.
    \item \textbf{Συγχρονισμός και αποφυγή ανταγωνισμού}: Πριν από οποιαδήποτε ανάγνωση του πίνακα \texttt{ptable.proc}, αποκτάται το κλείδωμα \texttt{ptable.lock}. 
    \item \textbf{Συλλογή υποψήφιων διεργασιών}: Διατρέχεται ο πίνακας \texttt{ptable.proc} και συλλέγονται σε πίνακα δεικτών \texttt{candidates[]} αποκλειστικά οι ζωντανές διεργασίες (αποκλείοντας καταστάσεις \texttt{UNUSED} ή \texttt{ZOMBIE}).
    \item \textbf{Τυχαία επιλογή και τερματισμός}: Εφόσον \texttt{count > 0}, επιλέγεται μία διεργασία τυχαία (\texttt{rand() \% count}). Απελευθερώνεται το κλείδωμα και καλείται η \texttt{kill(victim->pid)}. Αν δεν υπάρχει υποψήφια διεργασία, επιστρέφεται \texttt{-1}.
\end{itemize}

\clearpage
\subsection*{3. Υλοποίηση Κλήσης Συστήματος (\texttt{sys\_killrandom})}
\begin{lstlisting}[language=C, caption={Υλοποίηση sys\_killrandom στο kernel/sysproc.c}]
int sys_killrandom(void) {
  struct proc *candidates[NPROC], *p;
  int count = 0;

  // 1. Συλλογή ζωντανών διεργασιών (εξαίρεση init και τρέχουσας)
  for (p = ptable.proc; p < &ptable.proc[NPROC]; p++) {
    if (p->state == UNUSED || p->state == ZOMBIE) continue;
    if (p->pid <= 1 || p == proc) continue;
    candidates[count++] = p;
  }
  if (count == 0) {
    return -1;
  }
  // 2. Τυχαία επιλογή υποψήφιας διεργασίας
  int chosen_idx = (int)(rand() % (unsigned int)count);
  struct proc *victim = candidates[chosen_idx];

  // 3. Τερματισμός επιλεγμένης διεργασίας
  kill(victim->pid);
  return victim->pid;
}
\end{lstlisting}

\subsection*{4. Πρόγραμμα Χρήστη (\texttt{user/killrandom.c}) \& Πειραματική Επαλήθευση}
\begin{lstlisting}[language=C, caption={Πρόγραμμα χρήστη killrandom (user/killrandom.c)}]
#include "types.h"
#include "user.h"

int main(int argc, char **argv) {
  printf(1, "Killed pid %d\n", killrandom());
  exit();
}
\end{lstlisting}

\begin{lstlisting}[style=termstyle, caption={Δοκιμές τυχαίου τερματισμού διεργασιών στο τερματικό του xv6}]
$ sh &
$ sh &
$ killrandom
Killed pid 4
zombie!
$ killrandom
Killed pid 2
init: starting sh
$ killrandom
Killed pid 6
zombie!
\end{lstlisting}

Οι background διεργασίες (\texttt{sh \&}) υιοθετούνται από την \texttt{init} και όταν τερματίζονται, 
η \texttt{wait()} τις περισυλλέγει και η \texttt{init} τυπώνει \texttt{zombie!} (\texttt{wpid != pid}).

\noindent\begin{minipage}{\linewidth}
Στο \texttt{user/sh.c}, η περίπτωση \texttt{BACK} δημιουργεί τη background διεργασία με
\texttt{fork1()}, χωρίς να περιμένει τον τερματισμό της. Η ενδιάμεση διεργασία που
χειρίζεται την εντολή τερματίζεται με την \texttt{exit()} μετά το \texttt{switch}:
\begin{lstlisting}[language=C, caption={Απόσπασμα της runcmd στο user/sh.c}]
  case BACK:
    bcmd = (struct backcmd*)cmd;
    if(fork1() == 0)
      runcmd(bcmd->cmd);
    break;
  }
  exit();
\end{lstlisting}
\end{minipage}

Όταν τερματίζεται ο γονέας, η \texttt{exit()} του πυρήνα αναθέτει τα παιδιά του στην
\texttt{init}. Έτσι εξηγείται η υιοθεσία των background διεργασιών:
\begin{lstlisting}[language=C, caption={Υιοθεσία ορφανών διεργασιών στην exit του kernel/proc.c}]
  // Pass abandoned children to init.
  for (p = ptable.proc; p < &ptable.proc[NPROC]; p++)
  {
    if (p->parent == proc)
    {
      p->parent = initproc;
      if (p->state == ZOMBIE)
        wakeup1(initproc);
    }
  }
\end{lstlisting}

Αντίθετα, όταν τερματίζεται το ίδιο το ενεργό κέλυφος (\texttt{wpid == pid}), 
ο βρόχος αναμονής σπάει και η \texttt{init} επανεκκινεί άμεσα νέο shell τυπώνοντας \texttt{init: starting sh}.

Αυτό φαίνεται στον εξωτερικό βρόχο της \texttt{init}: η \texttt{pid} κρατά το PID του
shell που δημιούργησε, ενώ η \texttt{wpid} παίρνει το PID κάθε παιδιού που περισυλλέγει
η \texttt{wait()}. 

Για άλλο παιδί τυπώνεται \texttt{zombie!}, ενώ για το συγκεκριμένο
shell ολοκληρώνεται ο εσωτερικός βρόχος και αρχίζει νέα επανάληψη του \texttt{for(;;)}:

\begin{lstlisting}[language=C, caption={Δημιουργία shell και περισυλλογή παιδιών στο user/init.c}]
  for(;;){
    printf(1, "init: starting sh\n");
    pid = fork();
    if(pid < 0){
      printf(1, "init: fork failed\n");
      exit();
    }
    if(pid == 0){
      exec("sh", argv);
      printf(1, "init: exec sh failed\n");
      exit();
    }
    while((wpid=wait()) >= 0 && wpid != pid)
      printf(1, "zombie!\n");
  }
\end{lstlisting}
